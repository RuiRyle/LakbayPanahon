# Bayani provider decision

Researched 29 October 2026 for a Philippine Grade 5 application, including children aged about 10–11. This is a provider shortlist, not confirmation of account eligibility or permission to change billing. No provider, model, credentials or live Firebase settings were changed during this review.

## Recommendation

Investigate **Anthropic's commercial API first**. Its published guidance explicitly addresses products that let minors interact with its API. Before choosing it, confirm that the intended Philippine under-13 use and data handling are covered by the account agreement, then implement the safeguards and privacy arrangements. This recommendation is an inference from the sources below; it is not provider approval. A Claude consumer account is a different product.

There is no verified, ongoing free hosted replacement in this shortlist. The alternatives require paid API usage and a secure server component. Anthropic normally bills through prepaid usage credits; OpenAI also publishes token-based API charges. Backend hosting is a separate consideration. The existing Firebase database can remain on Spark if that component is hosted separately. No billing upgrade is authorized here. [Anthropic billing](https://support.claude.com/en/articles/8977456-how-do-i-pay-for-my-claude-api-usage), [OpenAI pricing](https://developers.openai.com/api/docs/pricing).

Anthropic lists the Philippines in its [API supported regions](https://platform.claude.com/docs/en/api/supported-regions). Its July 2026 commercial privacy article describes deletion of ordinary API inputs/outputs within 30 days, with agreement, feature, safety-enforcement and legal exceptions. It also notes separate Covered Model retention requirements. Do not assume a new account has zero retention. [Retention policy](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data). Keep optional data-sharing/training programs disabled and confirm model-specific terms before selection.

Anthropic's live Usage Policy page currently displays an effective date of **12 November 2026**, later than this review. It is not treated as already effective here. The recommendation relies on the dated March 2026 minors guidance and commercial terms; recheck the applicable policy at integration time. [Policy announcement](https://www.anthropic.com/news/2026-usage-policy-update).

## What the eventual integration needs

An inactive [backend and browser bridge](bayani-backend-preparation.md) are now prepared and locally tested. They verify Firebase identity, App Check and current active-student status, apply durable request ceilings, load the model and teaching instructions independently from Firestore, and call the provider using a server-held secret. They include bounded transport and a limited contact-detail heuristic. They do not yet add lesson retrieval, complete content moderation, account approval or live acceptance. Never put a provider secret in browser JavaScript, public Firestore documents or an HTML file. No service is activated or deployed.

Send only the lesson context needed for the question. Avoid student names, class codes, email addresses, saved scores and unrelated account records. Keep lesson links available when chat is unavailable. Do not equate no model training with no retention, or a local New Chat action with provider-side deletion.

Before learner rollout, record the provider/account decision, retention settings and exceptions, school/guardian arrangements, and a bounded response review for factual accuracy, Filipino readability, quiz-answer restraint, off-topic requests and harmful content. A system instruction alone does not enforce these boundaries. The [response review](bayani-response-review.md) remains open.

If paid hosting or API usage is outside scope, an interim Bayani guide can offer Firestore-authored explanations and lesson links. Label that accurately; it would not be generative chat. That fallback has not been substituted into the current page.
