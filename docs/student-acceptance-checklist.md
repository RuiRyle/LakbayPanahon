## Completion rules

**Local pass** means the named code/tests or mocked browser behavior passed. It does not mean the real database, published website or a child's understanding passed. Current results are in [the local report](validation/student-acceptance-local.json); the fixed [test plan](student-acceptance-plan.json) maps criteria to suites and records source hashes when run.

**Student implementation frozen** means independent student functionality has no unresolved acceptance defects, the remaining manual/local checks below pass, the bounded live security/save check passes, reviewed content is published/read back, and normal learning mode is confirmed after the user finishes exploration. Preserve the user's current preview until then. Do not mark this milestone complete from local tests alone.

**Student public release ready** additionally requires the privacy/operator process, learning review, intended hosted build and release acceptance. Stronger grading and paid AI are explicitly inactive; recording them as deferred preparation must not imply they protect or tutor real students. The existing browser-grading trust limitation remains visible in project reporting.

**Classroom integration accepted** is a separate later milestone. Freeze the student join/view/leave contract now; verify teacher-created data against it when teacher development is authorized. Only actual integration defects should reopen student implementation. Teacher authoring, announcements, individual feedback and new submission/grade mechanics are not existing student features and are not prerequisites for freezing independent learning.

## Fixed My Class contract

Students consume existing `classes`, exact `classJoinCodes` and published `classAssignments`; they own only their `classMembers/{uid}_{classId}` membership. The [class-flow specification](student-class-flow.md) defines current fields and rules. Completion uses saved mission progress, including work before joining; due dates are informational in Philippine time; assignments grant no extra XP and do not bypass learning locks. Leaving removes membership, not learning records. Archived classes disable lesson actions. Unavailable assignments/progress are not presented as an empty class or zero completion.

Teacher implementation must honor this contract or propose a deliberate migration with focused student regression checks. Later integration checks: create/publish as the owning teacher, join as a student, hide drafts/other rosters, complete an assignment through ordinary learning, rotate/revoke the code, archive, and leave. Existing student rules do not automatically grant teachers roster/progress access; teacher ownership rules require separate review.
